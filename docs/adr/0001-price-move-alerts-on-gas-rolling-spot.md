# 価格変動アラートは Google Apps Script 上で、スポット価格のローリング差分で判定する

## Status

accepted

## Context / Decision

USD/JPY が短時間で急変動したとき（5分で25pips以上）にスマホへプッシュ通知したい、という要望から検討した。当初は「Netlify で実現できるか」「5分足で」という前提だったが、いずれも採用しなかった。

- **実行場所は Netlify ではなく Google Apps Script。** 通知はアプリを閉じていても届く必要があるため、監視はブラウザではなくサーバー側の常駐ジョブになる。プロジェクトは既にレート取得で GAS を使っており、GAS の時間トリガー（1分間隔）＋ `PropertiesService`（状態保存）＋ `UrlFetch`（Twelve Data / Telegram 呼び出し）だけで完結する。Netlify を採用すると、本番が GitHub Pages である現状に対し関数専用の別プロジェクトかホスティング移行が必要になり、状態保存に Netlify Blobs を追加する必要も生じる。既存インフラの再利用が明確に単純。

- **トリガーはローソク足(OHLC)ではなく「ローリング5分スポット差分」。** `|price(now) − price(now−5min)| ≥ 25pips` で判定する。真の5分足レンジ(高値−安値)や実体(終値−始値)を使うには OHLC 提供APIが要る。無料で分単位のスポット価格が取れる Twelve Data を使う方針としたため、確定足ではなくスポットのローリング差分で近似する。用語の詳細は [CONTEXT.md](../../CONTEXT.md) を参照（「5分足」＝ローリングスポット差分であって候足ではない、と明記済み）。

## Consequences

- **データ源の制約が設計を縛る。** Twelve Data 無料枠は 800 req/日。GAS 最小間隔の1分ポーリングを24時間回すと 1440 req/日で超過するため、**平日15:00〜26:00 JST（ロンドン+NY重複の高ボラ帯、約11h、≈660 req/日）に限定**して1分間隔で監視する。東京時間の早朝は対象外。
- **判定はローソク境界に一致しない。** ローリング窓のため、確定足の値動きとは厳密には異なる。窓内でスパイクして戻る動きは取りこぼし得る。
- **連発防止に15分クールダウン。** 発火後15分は再通知を抑止（最終発火時刻を `PropertiesService` に保存）。
- **ウォームアップが必要。** セッション開始直後の5分間は5分前サンプルが無いため通知しない。
- **秘匿情報。** Telegram bot token / chat_id と Twelve Data API キーは GAS の Script Properties に保存し、リポジトリには含めない。
