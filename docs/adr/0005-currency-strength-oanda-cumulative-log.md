# 通貨強弱は OANDA 方式（対数変化率の合算・起点から0ベースの累積折れ線）にする

## Status

accepted（[ADR-0004](./0004-currency-strength-intraday-on-cloudflare-workers.md) を差し替え。インフラ(Cloudflare Worker + Cron + KV)は継続）

## Context / Decision

「OANDA の通貨力バランスと同じロジックにしたい／無料枠に収めたい」という要望による。
OANDA 方式の要点は、①主要8通貨、②各通貨が絡むペアの**対数変化率を合算**、③クォート側のペアは 1/価格 で向きを統一、
④選択した起点（4時間前/当日/年初）から **0 ベースで累積**、⑤プラス=強い/マイナス=弱い。

- **指標を「等加重の平均%変化」から「対数変化率の合算」に変更。** 各通貨 C の強弱を
  `Σ_(D≠C) [ (lnC_i − lnC_start) − (lnD_i − lnD_start) ] × 100`（JPYは基軸で0）とする。
  クロスレート `X/Y=(X/JPY)/(Y/JPY)` を使うため、OANDAの「1/価格で反転」も数学的に等価に処理される。
  各時点で総和≈0、起点で全通貨0。計算式はフロントと Worker で共有（`src/lib/strength.ts` の `computeCumulativeStrength`、単体テスト済み）。
- **表示を棒グラフから「0基準の累積折れ線（8本）」に変更。** 依存を増やさないため軽量な自作 SVG チャートで描画。
  凡例に現在値を強い順で表示。起点は 4時間前/当日/年初 をボタンで切替。
- **データはインフラ(Cloudflare Worker + Cron + KV)を継続。** ただし単一スナップショットではなく時系列をキャッシュする。

## Consequences

- **無料枠に収めるため更新頻度を調整。** Twelve Data は credits=シンボル数課金（期間長に依らず1回7credits）。
  - 15分足（当日＋4時間前をカバー、outputsize≈130）を **2時間ごと**：12回/日 ×7 = 84/日
  - 日足（年初をカバー、outputsize≈300）を **1日1回**：7/日
  - 合計 ≈ **91 credits/日**。価格アラート(≈660/日)と共有しても無料枠800/日以内。
  - 代償：4時間前/当日の値は最大2時間遅れ、年初は1日1回更新。
- **起点はクライアントで計算。** Worker は時系列(intraday/daily)をKVに保存するだけ。クライアントが
  選択起点のインデックスを求めて累積を計算するため、起点切替で追加のAPI呼び出しは発生しない。
- **cold-start対応。** KVが空なら fetch ハンドラが初回のみ取得して保存。
- **OANDAの数値とは一致しない。** 対象通貨・対数・合算は合わせたが、OANDAの独自の重み・足種・丸めまでは
  再現しないため、傾向は近くとも数値は一致しない。
- **秘匿情報。** Twelve Data キーは引き続き Worker シークレットのみ。クライアントは Worker URL(`VITE_STRENGTH_URL`)だけを持つ。
